## 2026-09-16 18:5X - 修复 CI 失败：tests 包导入问题

- **目标**：修复 commit `b776804` 推送后 CI 全矩阵失败的问题。
- **上下文锚点**：CI run 35126209844（b776804）三个测试 job 均 `跑测试` 步骤失败；构建检查 job 成功。
- **关键改动**：
  - `tests/__init__.py`（新）：给 tests 加包标记。
  - `tests/test_{cli,cache,separation,audio_io,transcription}.py`：`from conftest import` → `from tests.conftest import`（5 处）。
- **决策与理由**：
  - 根因：本地用 `python -m pytest`（cwd 在 sys.path，`tests` 是可发现的命名空间包）验证通过；CI 用 `pytest` 入口脚本，sys.path 无仓库根 → `from tests.conftest import` 报 `ModuleNotFoundError: No module named 'tests'`。
  - 选「加 `__init__.py` + 统一 `tests.conftest` 导入」而非「CI 改 `python -m pytest`」：前者让任意调用方式都稳定可导入，不依赖调用习惯；且 pyproject 的 packages include 只有 `musiclab*`，tests 不会被打进 wheel。
- **踩坑 / 修复**：
  - 首次只加 `__init__.py` 后，旧测试的裸 `from conftest import` 失效（pytest prepend 模式插入的 basedir 从 tests/ 变为仓库根）→ 统一改成 `tests.conftest` 前缀。
  - 轮询 Actions API 时 `json.load` 严格模式被响应中控制字符卡住 → `strict=False`。
- **验证结果**：本地 `pytest` 与 `python -m pytest` 两种方式均 122 passed；推送 `f213d79` 后 CI run 35126566116 全绿（success）。
